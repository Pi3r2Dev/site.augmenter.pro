# Backlog de boucle — maillage hiérarchisé du cluster Claude / Odoo / MCP

Source : audit du maillage du 2026-10-14 (session Claude Code, Search Console
sur 3 mois). Objectif : que les pages qui ont du poids chez Google transmettent
vers la landing `/serveur-mcp-odoo` et le workflow technique
`/blog/claude-code-odoo-workflow`, qu'aucun article de l'essaim ne soit orphelin,
et que le bloc « articles liés » cesse de renvoyer partout vers les trois mêmes.

Format : `- [ ] **ID [machine|humain]** -- tâche`. Une tâche qui **attend** une
autre reste `[machine]` avec `(apres ID)` en fin de ligne, jamais `[bloquee]` :
un `[bloquee]` posé à la main ne repart jamais seul. Seul le runner pose `[bloquee]`.

Ancres canoniques (une destination = une ancre stable, variantes grammaticales
tolérées seulement si la phrase l'exige) :

| Destination | Ancre |
| --- | --- |
| `/serveur-mcp-odoo` | « notre serveur MCP pour Odoo » |
| `/blog/claude-code-odoo-workflow` | « le workflow technique Claude Code + Odoo » |
| `/integration-mcp` | « intégration MCP pour PME » |
